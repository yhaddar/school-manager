# Decision Register

| ID | Decision | Status | Reasoning and impact | Related requirements |
|---|---|---|---|---|
| FD-001…FD-050 | Functional decisions defined in `AGENTS.md` | **Approved** | Product baseline; no change made by this register. | All |
| TD-001 | Laravel versioned JSON API with OpenAPI as contract authority and derived Postman collection | **Selected for foundation** | `openapi.yaml` is the checked-in authority for the current health and tenant-context contract; Postman is initialized locally in guest mode. Collection publication is intentionally deferred until stable authenticated operations exist. | FD-042, 048 |
| TD-002 | Flutter feature-first architecture with repositories, typed routes and Riverpod-style state management | **Proposed** | Testable separation and strong mobile/RTL support. Alternative: Bloc, at higher ceremony. | FD-044–046 |
| TD-003 | Shared PostgreSQL database/schema with enforced `institution_id`, policies, scopes and negative tests | **Selected for application design; local SQLite only** | Lowest operational burden for launch, with strict isolation controls. The first migrations were smoke-tested on SQLite; PostgreSQL compatibility remains mandatory before any release. | FD-001, 038–039, 042–043 |
| TD-004 | Redis for queues/cache/rate limiting; private S3-compatible storage | **Proposed** | Fits Laravel asynchronous work and private artifacts. Requires vendor/cost approval. | FD-011, 041, 047–048 |
| TD-005 | Short-lived opaque bearer access tokens; hashed rotating refresh tokens with reuse detection and current-session revocation | **Selected for foundation** | The Laravel session slice stores only token hashes, rotates refresh tokens transactionally and revokes the session on reuse. Per-device inventory, revoke-all and MFA remain later work. | FD-003, 031, 042–043 |
